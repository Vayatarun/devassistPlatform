Your First AnalysisAnalyze a project folder in one command

ℹ
The most common use case — point the analyzer at any C# project folder and get a full report in seconds.

Basic folder analysis

Analyze a folder
bash
dotnet run --project CodeReviewReporter -- \
  --path "C:\MyProject" \
  --html \
  --json

What happens step by step

1

File discovery

All .cs files are found recursively, excluding \bin\ and \obj\ folders.

2

Cache check

Each file's SHA-256 hash is compared to analysis_cache.json. Unchanged files are skipped instantly.

3

Dual pipeline analysis

Roslyn DiagnosticAnalyzers + 55 custom IRule rules run in parallel (CPU-bounded) for each file.

4

Quality Gate evaluation

Critical and error counts are checked against thresholds. Result: PASSED ✔ or FAILED ✘.

5

Reports generated

CodeReviewIssues.xlsx always. CodeReviewReport.html and CodeReviewReport.json when requested.

Other analysis modes

Quality GateAutomatically pass or fail your build

The Quality Gate is a configurable pass/fail checkpoint — the same concept as SonarQube's Quality Gate. It prevents bad code from merging when issues exceed your thresholds.

✔ PASSED

  • ✅ 0 critical issues (≤ max-critical)
  • ✅ 3 error issues (≤ max-errors: 5)
  • ✅ Build continues normally
  • ✅ Exit code: 0

✘ FAILED

  • ❌ 3 critical issues (> max-critical: 0)
  • ❌ 12 error issues (> max-errors: 5)
  • ❌ Failure reasons listed
  • ❌ Exit code: 1 (with --fail-on-gate)

Example — Strict CI pipeline

Zero-tolerance gate
bash
dotnet run --project CodeReviewReporter -- \
  --git \
  --max-critical 0 \
  --max-errors 0 \
  --fail-on-gate \
  --html

Writing a Custom RuleAdd a new rule in under 5 minutes

💡
No registration or config change needed. Create the class → build → run. RuleLoader discovers it automatically via reflection.
1

Create the file

Add a new .cs file in Analyzer1.Rules/<Category>/

2

Implement IRule

Fill in Metadata (RuleId, Title, Severity, Remediation) and the Analyze() method.

3

Build and run

The rule is live immediately — no restart, no config file changes.

Analyzer1.Rules/Design/TooManyPropertiesRule.cs
C#
using Analyzer.Core.Enums;
using Analyzer.Core.Interfaces;
using Analyzer.Core.Models;
using Analyzer.Rules.Attributes;
using Microsoft.CodeAnalysis.CSharp.Syntax;

namespace Analyzer.Rules.Design
{
    [RuleCategory("Design")]
    public class TooManyPropertiesRule : IRule
    {
        private const int MaxProperties = 15;

        public RuleMetadata Metadata => new RuleMetadata
        {
            RuleId          = "DES008",
            Title           = "Class has too many properties",
            Category        = "Design",
            DefaultSeverity = Severity.Warning,
            Remediation     = "Split the class into smaller focused classes.",
            EffortMinutes   = 30,
            Tags            = new[] { "design", "srp" }
        };

        public IEnumerable<CodeIssue> Analyze(AnalysisContext context)
        {
            if (context.SyntaxRoot == null) yield break;

            foreach (var cls in context.SyntaxRoot
                .DescendantNodes().OfType<ClassDeclarationSyntax>())
            {
                int count = cls.DescendantNodes()
                    .OfType<PropertyDeclarationSyntax>().Count();

                if (count > MaxProperties)
                    yield return new CodeIssue
                    {
                        RuleId      = Metadata.RuleId,
                        Message     = $"Class '{cls.Identifier.Text}' has {count} properties.",
                        Line        = cls.GetLocation()
                                        .GetLineSpan().StartLinePosition.Line + 1,
                        Severity    = Metadata.DefaultSeverity,
                        Category    = Metadata.Category,
                        Remediation = Metadata.Remediation
                    };
            }
        }
    }
}

CI/CD IntegrationBlock bad merges automatically

GitHub Actions

.github/workflows/code-analysis.yml
yaml
name: Code Analysis
on: [push, pull_request]

jobs:
  analyze:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with: { dotnet-version: '8.0.x' }

      - name: Build
        run: dotnet build Analyzer1.sln

      - name: Run CodeAnalyzer Pro
        run: |
          dotnet run --project CodeReviewReporter -- \
            --path ${{ github.workspace }} \
            --html --json \
            --max-critical 0 --max-errors 10 \
            --fail-on-gate

      - name: Upload Reports
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: code-analysis-report
          path: |
            CodeReviewReport.html
            CodeReviewReport.json
            CodeReviewIssues.xlsx

Next StepsYou're ready — here's what to do now

Immediate actions

1

Fix all Critical Security issues first

Filter the report by Severity = Critical + Category = Security. These are exploitable vulnerabilities — SQL Injection, XSS, hardcoded credentials.

2

Address empty catch blocks and missing dispose

Stability issues hide real errors in production. Fix STAB001 (EmptyCatch) and STAB003 (MissingDispose) next.

3

Set up CI/CD gate

Add the GitHub Actions or Azure DevOps pipeline snippet. Set --max-critical 0 so new security issues never merge.

4

Run on git diff for PR reviews

Use --git mode to analyze only changed files — fast enough to run on every pull request.
